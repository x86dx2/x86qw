# x86QW public contracts 1.0

This document freezes the public document and JSON-output contracts delivered
by PR C (issue #53). It is the reference for readers, writers, and tests. The
scope is deliberately limited to contracts; gameplay, downloads, host and
supervisor behavior, trust/promotion, future fixtures, and generated bundles
are outside this contract.

## Versioning

All newly parsed release versions use strict [Semantic Versioning 2.0.0].
`1.0.0-rc.1` is a valid prerelease and sorts after beta versions and before
`1.0.0`; build metadata does not affect precedence. Prerelease identifiers are
compared numerically when both identifiers are numeric and lexically otherwise.

The historical stable-version helper remains available for the 0.7 line and
accepts only a stable `MAJOR.MINOR.PATCH` value. Callers that need release
ordering, catalogs, archives, or bootstrap validation must use the full
SemVer parser so `1.0.0-rc.1` is accepted and ordered correctly.

## Versioned documents

The contract version fields and the current CLI compatibility floor are:

| Document | Explicit field | Current value |
| --- | --- | --- |
| catalog | `catalog_version` | `1` |
| install state | `state_version` | `2` |
| CLI receipt | `receipt_version` | `1` |
| all explicit documents | `min_cli_version` | `0.7.0` |

An explicit schema version requires `min_cli_version`. `max_cli_version` is
optional, but when present it must not be lower than the minimum. Readers keep
the legacy 0.7 `format` documents readable where the surface permits it;
writers emit the explicit field for their own document kind. Unknown schema
versions and incompatible CLI ranges are rejected with a contract error.

Catalog snapshots are validated as JSON objects and must retain immutable
coordinates for entries that describe a release. Duplicate object keys are
rejected instead of being silently overwritten.

## JSON command output

With `--json`, supported commands emit one deterministic UTF-8 document with
this envelope:

```json
{
  "schema_version": 1,
  "command": "status",
  "ok": true,
  "exit_code": 0,
  "dry_run": false,
  "data": {},
  "errors": []
}
```

The command is one of `version`, `status`, `hub`, `verify`, `repair`, `update`,
or `upgrade`. Mutating command names are JSON-safe only with `--dry-run`.
Data shapes are closed and versioned; unknown fields are errors. Output is
canonical (sorted keys, compact separators, UTF-8, no ANSI or prompts), and
duplicate input keys, invalid control characters, non-finite values, and
unbounded fields are rejected. Structured data and embedded URL credentials
are redacted before serialization. Exit codes remain stable: `0` success,
`1` operational failure, `2` usage/contract failure, and `130` interruption.

## `1.0.0-rc.1` rollout surfaces

The release candidate is accepted by the following real writers/readers:

- release builders and result ordering;
- installer-history archive validation and its embedded bootstrap helper;
- repository catalog loading/validation and catalog emission;
- install-state and CLI-receipt writers;
- manager version JSON output and release ordering.

The embedded helper source is regenerated from the standalone archive module;
no installer or release bundle is rebuilt as part of this contract change.

[Semantic Versioning 2.0.0]: https://semver.org/spec/v2.0.0.html
