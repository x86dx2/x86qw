# 0.7.2 — trust in the stable ezQuake on macOS

This note records the corrective implementation of issue
[#50](https://github.com/x86dx2/x86qw/issues/50). It is not release evidence
and does not authorize publishing or promoting version `0.7.2`.

## Baseline

- initial code: `206adc46df6aced49eee7ac1fcae3cf331f07a63`;
- preserved public release: `x86qw-installer-0.7.1`;
- stable artifact: ezQuake `3.6.9` universal macOS;
- decision: [ADR 0004](../adr/0004-preservar-bundle-upstream-ezquake-stable-macos.md).

## Reproduced defect

`prepare_macos_app()` served stable and nightly, changed `Info.plist`, removed the
sandbox through an ad hoc re-signing and made the receipt record the
transformed executable. The old test required exactly that result.

The upstream artifact has an ad hoc signature, hardened runtime and sandbox, but
no Team ID nor a stapled ticket, and is rejected by `spctl`. So preserving the
upstream fixes the degradation x86QW caused without making a false claim of
Developer ID or notarization.

## Implementation

- stable is extracted, inspected and promoted without changing any file;
- the transformation was isolated in `prepare_macos_nightly_app()` and fails if the
  channel is not nightly;
- host, verify, repair and update share a single per-channel decision;
- the 0.7.1 legacy is only identified by the pinned artifact, the binary identity,
  an `Info.plist` marker and, on macOS, the missing sandbox;
- legacy stable becomes `payload-required`; the installed CLI points to the bootstrap;
- the bootstrap's update restores the same version through a transactional commit;
- update, repair and installing the second channel preserve the shared macOS
  bookmark; the first-installation decision happens under the lock;
- nightly repair explicitly sets the platform and channel before the local
  routine, without depending on the installer's residual state;
- unknown artifacts, runtimes without a receipt and newer versions stay
  untouched;
- the catalog and the public projection tell `supported` from `conditional`;
- stable and nightly on macOS stay conditional until the native smokes.

## Preserved contracts

- stable and nightly keep coexisting;
- selection, version and channel undergo no conversion or downgrade;
- personal settings, PAKs, demos and logs take no part in the runtime swap;
- Linux, Windows, services and gameplay do not change;
- `0.7.1` and every published asset stay immutable.

## Changed contracts

- stable on macOS no longer gets an `Info.plist` change and a local signature;
- a stable installation transformed by the old line requires restoring the
  upstream payload through the bootstrap;
- `codesign --verify` is described as internal integrity, not authentication;
- macOS support for the clients is now declared conditional.

## Test evidence

The RED tests reproduced:

- mutation of the stable bundle;
- rejection of the sandboxed upstream bundle;
- an undue local repair of the legacy stable;
- no restoration on an update to the same version;
- undue inference when the executable already matches the upstream;
- undue inference of an unknown executable as the old transformation;
- accidental access to the signing routine through the stable channel;
- omission of the support state in the public projection.

The GREEN tests cover exact preservation of paths and bytes, the absence of
`codesign --sign`, rejection of an invalid signature before promotion, acceptance
of the upstream, restoration and rollback of the legacy, a conservative decision for
unknown artifacts and executables, coexistence without erasing the bookmark,
separation of nightly, conditional support and equivalence of the public projection.

Local validation on macOS on August 3, 2026:

- `PYTHONDONTWRITEBYTECODE=1 ./maintenance/manage.py verify`: passed;
- `python3 -m unittest discover -s maintenance/tests`: 765 tests run,
  730 passed and 35 explicit skips;
- `python3 -m unittest discover -s site/tests`: five tests passed;
- `git diff --check` and `git lfs fsck`: passed;
- `npm ci && npm run deploy:dry-run`: passed, 24 assets;
- the directly affected suite: 137 tests passed, one opt-in network smoke
  skipped.

Of the 35 local skips, 34 belong to the native Windows/Windows PowerShell cases
reserved for the matrix and one is the opt-in network smoke. The PR's canonical matrix is
[run 30871046055](https://github.com/x86dx2/x86qw/actions/runs/30871046055):
7/7 jobs passed. Ubuntu and macOS ran 765 tests with 35 skips on each
Python version; Windows ran the same 765 tests with 45 skips of
POSIX/macOS cases, plus the five site tests in every job. Native graphical
smokes are not replaced by that matrix.

## Residual risks

- the stable upstream stays ad hoc, without Developer ID or notarization;
- nightly still uses the pre-existing local ad hoc transformation;
- first/second launch and the sandbox bookmark need a real smoke;
- Gatekeeper, arm64, Intel and notched screens need the exact candidate;
- authentication, expiration and rollback of the metadata belong to PR 9;
- promotion without rebuild and native evidence belong to PRs 10 and 11.
