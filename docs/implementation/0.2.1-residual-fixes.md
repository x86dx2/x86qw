# Implementation note — residual fixes for 0.2.1

This note records the inspection that started the corrective line. It neither publishes nor
promotes version `0.2.1`.

## Baseline

- synced branch: `main`;
- HEAD analyzed before the changes:
  `3a95da88f7d6a978473115520ffe903560edfdd6`;
- public version: `0.2.0`;
- inventory: 49 packages, 21 components, five runtimes and five games;
- workflows: validation on Ubuntu, macOS and Windows with Python 3.10/3.13 and a protected
  manual release;
- initial tests: 226 maintenance tests, one documented network skip, and
  four site tests;
- Git LFS had to be materialized locally before the baseline passed.

## Reproduced problems

- recovery ran before any mutual exclusion between CLIs;
- PIDs without a creation token and without using the registered children in recovery;
- a modified sensitive configuration was preserved after a crash;
- the QTV upstream was always built on `127.0.0.1`;
- the external HTTP warning was wrongly conditioned on the upstream password;
- launchers without `repair` and Windows forwarding limited to `%9`;
- `repair` without full coverage of the clients and of partial metadata;
- `git diff --check` applied only to the clean checkout;
- arbitrary capabilities accepted in the format 2 state;
- runtime compatibility duplicated in the old component baseline;
- roadmaps with an outdated baseline and `0.2.0` publication gate.

## Already implemented at the initial HEAD

Safe POSIX validation of PK3/ZIP, private password input, preflight and
readiness, declarative catalogs, the state v1 to v2 migration and normal execution
without installing a permanent payload already existed. Those deliveries were preserved,
not presented again as new functionality.

## Corrective policy

An installation accepts a single active stack. Inconclusive locks and identities
fail conservatively. Processes are only terminated on an exact identity
match; modified personal and non-sensitive material is preserved;
sensitive ephemeral configuration is logically removed. Repair uses the recorded version and
channel and delegates the needed downloads to the validated bootstrap.
