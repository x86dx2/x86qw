# Nota de implementação — correções residuais para 0.2.1

Esta nota registra a inspeção que iniciou a linha corretiva. Ela não publica nem
promove a versão `0.2.1`.

## Baseline

- branch sincronizada: `main`;
- HEAD analisado antes das alterações:
  `3a95da88f7d6a978473115520ffe903560edfdd6`;
- versão pública: `0.2.0`;
- inventário: 49 pacotes, 21 componentes, cinco runtimes e cinco jogos;
- workflows: validação em Ubuntu, macOS e Windows com Python 3.10/3.13 e release
  manual protegida;
- testes iniciais: 226 testes de manutenção, um skip de rede documentado, e
  quatro testes do site;
- Git LFS precisou ser materializado localmente antes de o baseline passar.

## Problemas reproduzidos

- recuperação executada antes de qualquer exclusão mútua entre CLIs;
- PID sem token de criação e sem uso dos filhos registrados na recuperação;
- configuração sensível modificada preservada após crash;
- upstream QTV composto sempre em `127.0.0.1`;
- alerta HTTP externo condicionado incorretamente à senha de upstream;
- launchers sem `repair` e encaminhamento Windows limitado a `%9`;
- `repair` sem cobertura integral dos clientes e de metadata parcial;
- `git diff --check` aplicado apenas ao checkout limpo;
- capacidades arbitrárias aceitas no estado de formato 2;
- compatibilidade de runtime duplicada no baseline antigo de componentes;
- roadmaps com baseline e gate de publicação `0.2.0` desatualizados.

## Já implementado no HEAD inicial

Validação POSIX segura de PK3/ZIP, entrada privada de senhas, preflight e
readiness, catálogos declarativos, migração state v1 para v2 e execução normal
sem instalar payload permanente já existiam. Essas entregas foram preservadas,
não reapresentadas como funcionalidade nova.

## Política corretiva

Uma instalação aceita uma única stack ativa. Locks e identidades inconclusivos
falham de forma conservadora. Processos só são encerrados com correspondência
exata de identidade; material pessoal e não sensível modificado é preservado;
configuração efêmera sensível é removida logicamente. O repair usa a versão e o
canal registrados e delega downloads necessários ao bootstrap validado.
