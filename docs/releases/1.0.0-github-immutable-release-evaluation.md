# Evaluation of GitHub immutable releases

**Read on:** 2026-08-14 11:24 UTC
**Release observed:** `x86qw-installer-1.0.0-rc.1`
**Issue:** [#151 — Evaluate GitHub host-level immutable releases](https://github.com/x86dx2/x86qw/issues/151)

## Result

The release API reports `isImmutable=false`. The RC release must not be
changed to try this setting: it is already public, holds historical bytes and
the publisher cannot overwrite.

The current flow has logical immutability that does not depend on the
host-level setting:

- rejects extra assets on the release;
- compares the size and SHA-256 digest of each existing asset;
- uploads only missing assets;
- refuses to converge when an existing asset differs;
- requires the tag to point directly at the candidate's commit;
- treats the release as a prerelease and prevents it from being `Latest`.

This protection does not stop an administrative operation outside the
publisher from changing or removing assets. So `isImmutable=false` remains a
governance limitation and must not be described as strong immutability.

## Compatibility to validate before 1.0.0

Before turning the property on for a future release, run a rehearsal on a
throwaway tag or test candidate and confirm:

1. creating the release and uploading every asset still works;
2. a second, idempotent publish does not try to overwrite;
3. a digest mismatch is still rejected;
4. GitHub publishing, the GitLab mirror, mirror verification and
   metadata-last stay in the same order;
5. the API returns `isImmutable=true` without changing the assets/digests
   response the verifiers use;
6. a later failure does not require editing the release: recovery uses a new
   version/tag and a new TUF catalog.

## Decision

Do not turn on or modify the RC release at this checkpoint. The publisher and
the verifiers stay the active protection; turning on the host-level setting
is left for a deliberate change, tested and approved before the final
promotion or in a later release. Until then, the limitation stays recorded as
P2 and is not turned into a stronger security claim.
