# Avaliação de GitHub immutable releases

**Data da leitura:** 2026-08-14 11:24 UTC  
**Release observada:** `x86qw-installer-1.0.0-rc.1`  
**Issue:** [#151 — Evaluate GitHub host-level immutable releases](https://github.com/x86dx2/x86qw/issues/151)

## Resultado

A API da release informa `isImmutable=false`. A release RC não deve ser
alterada para experimentar essa configuração: ela já é pública, contém bytes
históricos e o publisher não pode executar overwrite.

O fluxo atual possui imutabilidade lógica independente da configuração
host-level:

- rejeita assets extras na release;
- compara tamanho e digest SHA-256 de cada asset existente;
- envia somente assets ausentes;
- recusa convergência quando um asset existente diverge;
- exige tag apontando diretamente para o commit do candidato;
- trata a release como prerelease e impede que ela seja `Latest`.

Essa proteção não impede uma operação administrativa externa ao publisher de
alterar ou remover assets. Portanto, `isImmutable=false` continua sendo uma
limitação de governança e não deve ser descrito como imutabilidade forte.

## Compatibilidade a validar antes da 1.0.0

Antes de habilitar a propriedade para uma release futura, executar um rehearsal
em um tag descartável ou candidato de teste e confirmar:

1. criação da release e upload de todos os assets ainda funciona;
2. uma segunda publicação idempotente não tenta overwrite;
3. divergência de digest continua sendo rejeitada;
4. publicação GitHub, mirror GitLab, verificação dos mirrors e metadata-last
   continuam na mesma ordem;
5. a API devolve `isImmutable=true` sem alterar a resposta de assets/digests
   usada pelos verificadores;
6. uma falha posterior não exige editar a release: a recuperação usa nova
   versão/tag e novo catálogo TUF.

## Decisão

Não habilitar nem modificar a release RC neste checkpoint. O publisher e os
verificadores continuam sendo a proteção ativa; a habilitação host-level fica
para uma mudança deliberada, testada e aprovada antes da promoção final ou em
um release posterior. Até lá, a limitação permanece registrada como P2 e não é
convertida em uma alegação de segurança mais forte.
