# x86QW 0.7.13

A hotfix of preparing ezQuake on macOS.

## Fix

- removes the old `basedir`, `version` and `NSOSPLastRootDirectory`
  preferences of the `com.ezquake.ezQuake` domain one by one;
- avoids importing the whole domain, which could return success without
  beating the active CFPreferences cache;
- confirms that each key is really gone before the install goes on;
- restores the original snapshot if any partial removal fails.

In 0.7.12, a clean install could reach ezQuake stable 3.6.9 and fail at the
`directory-preferences` step, even after validating the ZIP and the PAKs.
0.7.13 does the cleanup through the native per-key operation and keeps the
transactional rollback.

Release 0.7.12 stays historical and immutable. The public bootstrap now points
at the 0.7.13 bundle and at TUF metadata v11.

## Validation

- a RED regression reproducing the false success of the import with the
  CFPreferences cache;
- real removal and restore of the three preferences on macOS;
- 1,422 maintenance tests and five site tests;
- the protected matrix on Ubuntu, macOS and Windows with Python 3.10 and 3.13.
