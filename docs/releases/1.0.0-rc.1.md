# x86QW 1.0.0-rc.1

A public release candidate for the operational validation of x86QW.

> The historical record of the RC. The owner-only promotion was completed
> later, in the release
> [`x86qw-installer-1.0.0`](https://github.com/x86dx2/x86qw/releases/tag/x86qw-installer-1.0.0).
> The current state and the final hashes are in
> [`1.0.0-owner-only-publication-2026-08-15.md`](1.0.0-owner-only-publication-2026-08-15.md).

The current operating mode is `owner-only`: the maintainer is the only user
and can wipe the target before installing again. Migration from `0.7.x` is
kept for the future `external-public` audience, but it is not a requirement
to use or promote the product at this stage.

## Platform status

- macOS arm64/M3 stable: `conditional`, with native functional evidence;
- MVDSV, QTV and QWFWD on macOS arm64: support candidates during the soak;
- macOS nightly: `preview`;
- Intel macOS: `preview`;
- Linux: `preview`;
- Windows: `preview`.

`conditional` does not mean that Gatekeeper, notarization or the original
upstream identity were proven. `preview` does not mean that native execution
was approved.

## What to test

1. run the [Public release acceptance on Apple M3](../../.github/workflows/public-acceptance.yml)
   workflow with `acceptance_scope=single-user`;
2. install through the public bootstrap and catalog into a throwaway folder;
3. run `version`, `verify`, `changes`, `update`, uninstall and purge;
4. play KTX, Final Arena, Pro-X, Team Fortress and TD2;
5. test MVDSV, QTV and QWFWD;
6. report any P0/P1 failure with the platform, commit, hashes, logs and steps
   to reproduce.

The external soak stays without a formal opening because the audience is still
`owner-only`. Local rechecks and the protected workflow passed a clean
install, lifecycle, idempotent update, uninstall and purge. The
`0.7.13 → 1.0.0-rc.1` path is required again only when the maintainer
declares external users.

## Known limitations

- the GitHub release is not marked host-level immutable yet;
- the signed evidence used to promote this RC still depends on the protected
  artifact; future candidates materialize `release-evidence.json`,
  `evidence-root.json` and `release-receipt.json` as durable assets;
- the first two protected attempts of the M3 acceptance timed out on the
  M3's connection to Cloudflare; the final protected run `31845951477` passed
  and is recorded in [`1.0.0-rc.1-public-acceptance.md`](1.0.0-rc.1-public-acceptance.md);
  the optional real migration stays archived in
  [`1.0.0-rc.1-public-acceptance-migration-local-2026-08-14.json`](1.0.0-rc.1-public-acceptance-migration-local-2026-08-14.json);
- the RC is not `Latest` and does not replace the stable `0.7.13` bytes;
- at the time of this RC, the owner-only promotion of `1.0.0` was still
  blocked by the stage's gates; it was completed later in the final owner-only
  release. The external-public promotion stays blocked until the soak is done
  and the gates are repeated for an external audience.

## Incompatible changes

The recommended flow at this stage is a clean install into a throwaway
target. The `migrate` command and the `0.7.0–0.7.13` line stay in the product
for the future `external-public` transition, but they are not a compatibility
promise of the owner-only mode.
