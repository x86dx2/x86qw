# x86QW 1.0.0 — historical draft

> Status: **superseded**. The owner-only release is in
> [1.0.0-owner-only-publication-2026-08-15.md](1.0.0-owner-only-publication-2026-08-15.md).

This file keeps preparation notes. It does not describe the current state.
The source baseline in Git is still `0.7.13`; the GitHub Latest is `1.0.0`
owner-only.

The current cycle is `owner-only`: a single user can wipe the target and
install from scratch. Historical migration is a capability kept for the
future `external-public` transition, not a requirement of the first install.

## Planned scope

- SemVer, state, receipt and JSON output contracts frozen;
- the one-way migration capability kept for the future `external-public`
  audience;
- a downloader and a single-file boundary, with limits and atomic promotion;
- catalog and metadata authenticated by a rotatable trust root;
- a candidate built once and validated without a rebuild;
- the native M3 smoke run on the exact candidate, separate from the portable
  validation;
- factual documentation and release governance reviewed.

These runs do not replace the protected workflow's artifact/handoff, the

## Gates of the owner-only release

- a native M3 smoke of the final candidate, with signed evidence bound by
  hashes; the local `1.0.0-rc.4` checkpoint and the private `1.0.0` preflight
  already passed `25/25`, but neither is a final public candidate;
- durable evidence, a review of the candidate and the applicable trust
  controls;
- post-release validation on clean installs, with the protected workflow's
  artifact and handoff.

A seven-day soak, historical migration and sustainable TUF operation are gates
of the `external-public` transition, not of the owner-only release.

The historical `1.0.0-rc.4` checkpoint of commit
`76a73f9b50919010fc13730514d2c73ceced2fde` passed full M3 coverage on the
Apple M3 Pro. The private `1.0.0` preflight of HEAD
`f2cadeff3261ce07f7c9490313db1aa69e417fa2`, with `candidate.json`
`c7357159df806b29d8c9eb715152ec6186c5d9edefd3bb5587dbf6c98a0a94c7` and
installer `d3274e6aa2f1e3078ac5000ffae8b97c9efd329f3c2a87499bf1c57e5f388cb8`,
also passed `25/25`. These results do not replace the signed handoff, the
acceptance of the public endpoint or the soak.

None of the items above can be replaced by a synthetic fixture, an environment
variable or an unvalidated platform claim. Local promotion happens directly on
the Mac from an immutable candidate; the owner-only release keeps the
applicable bytes, evidence and P0/P1 gates. macOS-ARM64/M3 is the native gate
of this flow. Linux-X64, Windows-X64 and macOS-X64 stay kept as
compatibility/catalog and preview, without being presented as native
execution in this cycle.

The `.github/workflows/rc-soak.yml` workflow and the `verify-soak` job of
`.github/workflows/release.yml` make the external period an executable gate
when `release_audience=external-public`; a local receipt or an open issue
cannot stand in for the protected artifact.
