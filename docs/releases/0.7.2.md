# x86QW 0.7.2

A proposed corrective release that consolidates bounded boundaries for
incoming remote bytes, for reading and extracting ZIP, PK3 and PYZ and for
private objects on Windows, keeps the upstream macOS stable bundle intact and
moves the incremental `x86qw_runtime` boundaries forward.

> Status: **published and verified**. `0.7.2` is the `current` version; `0.7.1`
> and every earlier version stay immutable in the history.

Bundle: `x86qw-installer-0.7.2.zip` · 286103 bytes · SHA-256
`7f14caadce174665a24431eab4615833c657ad71a8cbe82f34b66c413857b6f0`.

## x86QW and KTX gameplay

- adds a selectable x86QW assisted ruleset, applied before the personal
  settings and without changing ezQuake's competitive rulesets;
- adds the opt-in Quad Coach for casual matches to the reproducible KTX QVM,
  without changing the weapon, health, skins or colors KTX manages;
- keeps the five games, the 24 KTX modes, the Frogbot profiles and the
  existing command-line contracts;
- updates the affected components with new immutable versions, keeping every
  previously published version available and unchanged.

## Download boundary

- centralizes Python's HTTP input in `maintenance/tools/downloader.py`;
- requires HTTPS, a limit and a deadline for every response;
- also requires a target, an exact size and a SHA-256 for persistent
  artifacts;
- centralizes the validation of persistent URLs in the catalog, manifest,
  release and upstream inventories and intake; rejects credentials, fragments,
  queries, spaces or control characters;
- keeps dynamic metadata in memory and forbids promoting an unpinned payload,
  in maintenance too;
- removes the transport callback, opener, clock, sleep and randomness from the
  public API; progress/retry callbacks stay, and each call creates its own
  private transport and cancelation registry;
- blocks new stable, nightly and nQuake versions before confirmation, staging
  or download until `add` has reviewed their size and SHA-256;
- replaces `git ls-remote` and the partial clone of nQuake with bounded queries
  for the reference, commit and recursive tree in GitHub's official API;
  rejects a truncated tree and validates the path, type, mode, SHA-1 and size
  of each entry;
- makes `add --dry-run` validate pins, portable paths, symlinks, collisions,
  owner, consumer, package and the proposed inventories without downloading
  or changing files; shows only redacted origins and rejects a persistent
  query;
- requires `managed: true` for every persistent remote and an exact link to a
  release artifact, a preserved source, a proposed public package or an nQuake
  reference; validates the namespace, consumer and logical package identity
  and keeps already recorded paths and installer bundles immutable;
- requires the ezQuake coordinates to match
  `clients/ezquake/<channel>/<version>/<platform>-<architecture>/<file>`
  exactly;
- limits paths to 240 UTF-16 units and rejects Win32 reserved characters,
  devices and aliases;
- copies local sources declared in the BOM through an exclusive temporary,
  with mode `0600` on POSIX, checks the plan while streaming and uses `fsync` +
  `replace`, without writing through a staging hardlink over the live `dist/`;
- computes the size and SHA-256 while streaming;
- rejects an invalid, duplicate or mismatching `Content-Length`;
- stops responses without a declared size once they go over the limit;
- uses a private temporary on POSIX and promotes only after validation,
  `flush`, `fsync` and close.

## Deadlines, retry and mirrors

- uses a monotonic deadline that covers connection, redirects, headers, reads,
  attempts and pauses;
- resolves DNS in an isolated subprocess, with bounded output and a stop
  followed by reaping on timeout;
- releases the resolver to `getaddrinfo` only after registering its handle; a
  late creation never gets the token and does not start DNS after the
  deadline;
- connects TCP candidates without blocking under the same deadline;
- interrupts TLS and headers with `shutdown` before closing the socket;
- applies the same coordinated stop when the controller is interrupted;
- rejects a remaining budget under 500 ms before creating a worker, resolver
  or socket;
- keeps the bootstrap's full connection/attempt timeout when the total
  deadline still holds the later cleanup margin;
- asks for the registered connection to be closed even when the deadline ends
  right after the worker starts, and closes late responses;
- offers `download_mirrors()` with prior validation and a single budget for
  every origin;
- allows a remote fallback only on a transport or integrity failure;
- treats protocol, limit, storage, policy and deadline failures as terminal,
  without masking them with another mirror;
- retries only transient network errors and HTTP 408, 425, 429, 500, 502, 503
  and 504;
- applies exponential backoff with jitter and honors `Retry-After` when it fits
  in the remaining budget.

## Bootstraps

- keeps minimal projections before the zipapp exists;
- ignores an inherited `.curlrc` with `curl --disable` as the first argument
  and restricts the origin and redirects to HTTPS;
- bounds the public Unix command with `head -c 262145`, checks the status and
  size before running and rejects a prefix produced by a failed pipeline or an
  oversized stream without `Content-Length`;
- shares the deadline between attempts and mirrors;
- closes intermediate redirect bodies without draining them;
- keeps HTTP 308 redirects on the minimum supported Python 3.10 too;
- validates the size, `Content-Length` and SHA-256 on each download;
- keeps the canonical and public copies equivalent.

## ZIP, PK3 and PYZ boundary

- creates `x86qw_runtime/io/archive.py` as the single boundary for scanning,
  reading and extracting ZIP, PK3 and PYZ;
- produces an `ArchivePlan` only after validating the envelope, every member,
  the real size, CRC, SHA-256, compression, type and portable names;
- rejects traversal, absolute paths, drives, backslashes, control characters,
  Windows reserved characters and devices, links, special types and exact,
  case, Unicode or prefix collisions;
- limits the number of members before allocating `ZipInfo`, the size per
  member, the compressed source, the central metadata, the expanded total, the
  depth, the UTF-16 path and the compression ratio;
- walks the central directory structurally before `zipfile`, preventing
  unbounded allocation or an underestimated count in the EOCD;
- copies the source into a private snapshot with a bounded read; the pre-scan
  and `ZipFile` read the same immutable bytes even under a concurrent swap;
- applies only the canonical modes `0644` and `0755` the product declares;
- extracts into a private staging, syncs files and folders and promotes
  without replacing an existing target;
- finishes every revalidation before the promotion and treats the published
  identity as an irreversible commit, keeping personal content on late
  failures;
- moves the installer, gameplay, services, maintenance tools, builders and
  site tests to the same contract;
- makes ephemeral materialization on Windows reversible through handles,
  `FILE_ID_128` identity, promotion without replacement and removal of the
  same confirmed object, without depending on a hardlink or on `DeleteFileW`
  by path;
- bounds recovery hashes to the member's exact size, keeps legacy journals
  without a size and uses a quarantine with a second validation in the POSIX
  cleanup;
- removes `unzip` and `Expand-Archive` from the candidate bootstraps through a
  byte-for-byte projection of the canonical module;
- validates the installer's exact historical layouts without weakening the
  modern seven-member contract;
- makes builders use a stable snapshot, staging under an explicit root and
  publishing without replacing a concurrent artifact, manifest or pointer;
- keeps the 59 existing ZIP/PK3/PYZ files compatible and adds a regression
  test that walks that inventory in CI.

## Private DACL on Windows

- creates a portable private filesystem boundary, with a Win32 adapter in the
  standard library and explicit `ctypes` signatures;
- creates managed files and folders with the access policy already present in
  `SECURITY_ATTRIBUTES`, with no window between creation and hardening;
- uses a protected DACL and exactly two full-control ACEs: the current user and
  `LOCAL SYSTEM`; folders propagate the policy only to their children;
- refuses reparse points, an unexpected owner, active inheritance, an extra
  principal, a filesystem without persistent ACLs or an inconclusive API
  result;
- applies the boundary to `.x86qw/`, sessions, locks, journals, stop requests,
  logs, sensitive settings, temporaries, staging, downloads and extractions;
- makes the PowerShell bootstrap create the private working folder before
  writing the helper, the bundle or extracted content;
- validates external password files through the same handle, without changing
  the owner, DACL, name or content;
- does not ask for elevation; the smoke under a standard account stays in
  PR 11;
- keeps a private leftover when the identity needed for the cleanup can no
  longer be proven, instead of deleting by pathname;
- formalizes the contract and its threat limit in
  [ADR 0003](../adr/0003-dacl-privada-windows.md).

This implementation belongs to the corrective candidate of PR 4. The native
Windows jobs with Python 3.10 and 3.13 validated its contract; the runtime
smoke under a standard account without elevation stays pending in PR 11. It
is not part of the public `0.7.1` release.

## Trusting ezQuake stable on macOS

- keeps the paths and bytes of the extracted upstream stable bundle exactly as
  they are;
- does not change the stable's `Info.plist`, sandbox, entitlements or
  signature;
- keeps the stable channel from reaching the ad hoc preparation, now exclusive
  to nightly;
- accepts `codesign --verify` only as a check of internal consistency;
- identifies the stable transformed by 0.7.1 only by its known artifact,
  binary identity and marker;
- restores the same version through the bootstrap with a transactional swap
  and rollback;
- keeps the installed CLI without downloading a payload and points to running
  the bootstrap again;
- keeps the shared bookmark on update, repair and the install of the second
  channel, deciding the first install only under the lock;
- fixes the platform/channel context of the nightly repair;
- projects macOS stable and nightly as `conditional` in the public catalog;
- records hashes, the decision and the limits in
  [ADR 0004](../adr/0004-preservar-bundle-upstream-ezquake-stable-macos.md).

Keeping the upstream intact does not make it Developer ID signed or notarized:
stable 3.6.9 stays ad hoc, without a Team ID or a stapled ticket, and is
rejected by `spctl`. Nightly keeps the pre-existing local transformation.
First/second launch, the sandbox bookmark, Gatekeeper, arm64, Intel and
notched screens stay in PR 11. This corrective implementation is not part of
the public `0.7.1` release.

## Incremental runtime boundaries

The documentation HEAD `29d76a48721190aad1203d0986a31d839d62070e` of PR 6:

- keeps `x86qw_runtime` independent of `maintenance`, `dist` and the installed
  entrypoints;
- centralizes the downloader, archive, atomic persistence, private filesystem,
  managed files, catalogs, state, receipts, migrations, transactions,
  navigation, gameplay, platform Python/locking/processes/ACL, the
  installation lock and the process/session supervisor;
- makes maintenance and the entrypoints use the canonical symbols, keeping
  facades only where a compatible consumer exists;
- publishes the CLI, preserved PAKs, defaults, repairs, migrations, cleanup and
  uninstall with inverses kept until the final logical result;
- produces a zipapp of exactly 56 members: 44 runtime modules, four top-level
  entrypoints/facades, two KTX projections and six generated members;
- declares the origin, consumer and contract of each member in
  `maintenance/inventory/installer-runtime-members.json`; the builder derives
  the projection from that manifest and the test requires it to equal the ZIP
  actually produced;
- removes maintenance modules and facades without a consumer from the
  artifact.

The code of this front was merged into the 0.7.2 candidate. `manager.py`,
`gameplay.py` and `services.py` stay as composition roots, while the console,
parser, navigation and reusable rules belong to the runtime. Cleanup,
uninstall and purge use a reversible quarantine until the commit. The full
local regression and the candidate's cross-platform matrix were run; the
native release smokes stay pending for the items that require them.

## Adversarial lifecycle fixes

- serializes in the kernel the observation and reclaiming of the
  per-installation lock, with `flock` on POSIX and a private mutex in the
  Windows global namespace;
- keeps two CLIs from reclaiming the same abandoned `active.lock` in parallel;
- rejects booleans where the lock schema requires integers;
- creates Windows processes suspended, assigns them to the Job Object before
  running runtime code and rolls back the leader or the tree on any failure;
- keeps the operational error when removing a private staging also fails,
  reporting the leftover without masking the original cause.

The adversarial review of PR 4 required these fixes, and they were exercised
in the native matrix before being considered done in the code.

## Limitations this release does not solve

- catalogs and dynamic metadata still have no signature, expiry, protection
  against rollback/freeze or key rotation; that is the scope of PR 9;
- the publishing commands through `gh` and `curl` stay under the immutable
  redesign of PR 10; they send bytes and are not ingestion routes. The GitLab
  upload `curl` already starts with `--disable`, requires HTTPS and does not
  follow redirects;
- a local process creation blocked inside the operating system cannot be
  canceled by a thread; the caller honors the deadline and the late child is
  killed before DNS/socket, but the daemon thread waits for `Popen` to return;
- a reap pathologically slower than the reserved window can finish in the
  daemon thread after returning; `kill` was already requested and no new
  DNS/socket activity is allowed;
- the static scanner does not replace reviewing reflection, generated code,
  native extensions or network libraries not inventoried yet;
- the private DACL reduces access between ordinary local users, but it does
  not protect against code running as the same user, an administrator who
  uses native privileges or a compromised kernel; the smoke of the runtimes
  under a standard account without elevation stays in PR 11;
- finishing the quarantine uses a validated handle on Windows and an
  unpredictable private name after an exclusive rename on POSIX; links and
  special types are kept. POSIX offers no conditional removal by inode and
  does not protect against hostile code running as the same user;
- the build-time sync of the bootstraps uses private staging and an atomic
  replace without following symlinks, but it still assumes an exclusive
  checkout because the standard library has no portable pathname CAS; PR 10
  will formalize that exclusivity in the candidate's promotion;
- portable downloader tests are not the same as native runtime smokes.
- the zipapp's declarative manifest generates the builder's projection and is
  validated against the file produced;
- the full integrated regression ran 1,197 maintenance tests, with 37 explicit
  skips, and five site tests; the PR 64 matrix passed in 7/7 jobs on Ubuntu,
  macOS and Windows with Python 3.10 and 3.13.

## Contracts kept

- no new runtime, game, mod, map or service;
- `0.7.1`, its hashes, bundles, tag and releases stay immutable;
- channel, version, profiles, personal settings and installed data do not
  change; the legacy stable is deliberately restored to the full upstream
  bundle;
- the existing gameplay and arguments stay compatible; the assisted ruleset
  and the Quad Coach are opt-in additions.
