This record is the operational notebook of the external usage period. The
release date does not turn downloads into users nor declare the soak done.
Closing it requires the canonical issue closed, evidence attached and an
authorized human review. In owner-only mode, the lack of that closing is a
parked pending item, not a blocker.

The automated closing must use `.github/workflows/rc-soak.yml` on the ref of
the RC's exact commit. The `rc-soak-<commit>-<run_id>-<run_attempt>` artifact
and its `report.json` are then checked by the `verify-soak` job of the
promotion workflow; local receipts do not satisfy that gate.

`report.json` uses `format: 2`: each handoff states `macos-arm64`, the M3
hardware model and an HTTPS evidence URL for each day. When dispatching the
workflow, `observation_evidence_b64` must be the base64 JSON with exactly the
same dates as `observed_dates`; missing, duplicate or non-HTTPS links make the
gate fail.

## Rules once the external-public mode is turned on

- no new product bytes, feature, engine, mod, map or PAK;
- a change to the candidate's bytes requires a new versioned RC and a restart
  of the period;
- the TUF monitor must stay healthy, with no expiry inside the alert window;
- a P0/P1 failure restarts the period after the fix and a new candidate;
- the failed public acceptance of RC.1 restarts the period only after a new RC
  is green and publicly accepted;
- incidents must point at the candidate and at the exact public bytes;
- Linux, Windows and Intel macOS stay `preview`; stable macOS stays
  `conditional` unless there is more evidence.
