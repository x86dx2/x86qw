**Período mínimo recomendado:** sete dias completos sem P0/P1, até
2026-08-20 UTC

**Release:** `x86qw-installer-1.0.0-rc.1`
**Commit de produto:** `a8758ee27bebd7c72c24a31dc19335652e260c0a`

**Issue canônica:** [#143 — RC soak](https://github.com/x86dx2/x86qw/issues/143)

Este registro é o caderno operacional do período de uso. A data de início é o
marco publicado da release; ela não transforma downloads em usuários nem
declara o soak concluído. O encerramento exige issue canônica fechada,
evidência anexada e revisão humana autorizada.

O encerramento automatizado deve usar `.github/workflows/rc-soak.yml` na ref do
commit exato do RC. O artifact `rc-soak-<commit>-<run_id>-<run_attempt>` e o
`report.json` são então conferidos pelo job `verify-soak` do workflow de
promoção; recibos locais não satisfazem esse gate.

O `report.json` usa `format: 2`: cada handoff informa `macos-arm64`, o modelo do
hardware M3 e uma URL HTTPS de evidência para cada dia. Ao despachar o workflow,
`observation_evidence_b64` deve ser o JSON base64 com exatamente as mesmas datas
de `observed_dates`; links ausentes, duplicados ou não HTTPS fazem o gate falhar.

## Registro de uso

Cada execução deve registrar data UTC, hardware, bytes públicos (catalog,
installer e candidate, quando disponíveis), resultado de `verify`, operações
executadas e link HTTPS para logs ou recibos. Não registrar tokens, chaves
privadas ou dados pessoais. O link diário deve ser público ou durável o
suficiente para a revisão posterior; o artifact de Actions continua sendo
apenas a embalagem autenticada do handoff.

## Regras durante o soak

- nenhum novo byte de produto, feature, engine, mod, mapa ou PAK;
- mudança nos bytes do candidato exige um novo RC versionado e reinício do
  período;
- monitor TUF deve permanecer saudável, sem expiração na janela de alerta;
- falha P0/P1 reinicia o período depois da correção e de um candidato novo;
- a falha de aceitação pública do RC.1 reinicia o período somente depois de um
  novo RC verde e aceito publicamente;
- incidentes devem apontar para o candidato e para os bytes públicos exatos;
- Linux, Windows e macOS Intel continuam `preview`; stable macOS continua
  `conditional` salvo evidência adicional.
