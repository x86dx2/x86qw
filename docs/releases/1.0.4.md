# x86QW 1.0.4

The source and the current installer move to `1.0.4`. `1.0.3`, `1.0.2`,
`1.0.1`, `1.0.0` and `0.7.13` stay in the catalog as historical, not as
current.

## What goes in

- a public bootstrap compatible with Windows PowerShell 5.1, without carrying
  multi-line Python programs through `python -c`;
- the TUF cache on Windows uses an authenticated regular file for `root.json`,
  so it no longer needs the privilege to create symbolic links (WinError 1314).

## What does not change

- the `owner-only` audience; `external-public` stays `NO-GO`;
- earlier packages and tags stay immutable;
- the SHA-256, size, ZIP and TUF metadata validation stays fail-closed.

## Verified operational state

- `MAIN=GREEN` in Validate `33135951867`;
- `TUF=HEALTHY`: root v1, timestamp v30 and snapshot/targets v29;
- the owner-only projection was repaired and verified in run `33136179763`;
- the current source is `1.0.4`; the published release is still the `1.0.0`
  owner-only candidate, valid for the maintainer on Apple M3.

The full state, including hashes, audience limits and parked gates, is in
[`RELEASE-TRUTH-CURRENT.md`](../post-1.0/RELEASE-TRUTH-CURRENT.md).

## Validation

- a regression test of the WinError 1314 failure and of catalog
  authentication;
- the native Windows PowerShell 5.1 harness for materializing the extractor;
- the portable Validate at the source cut.
