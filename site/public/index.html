Matches, servers and hosting in the same app.

The app and the CLI cover the whole cycle: play, host, join, update and verify. Stable and nightly live side by side.

play Play
Modes, maps and ruleset picked on the Play screen. Frogbots and the Quad Coach only where the QVM allows them.
host Host
Several MVDSV instances in one session, in the foreground or the background, with a preflight, a journal and a coordinated stop.
hub Join
Public servers, spectating and QTV. Favorites first; qw:// links and demos open straight in ezQuake.
update Update
A TUF-authenticated plan before anything is written. verify checks the SHA-256 of what is already on disk.
MVDSV · QTV · QWFWD
Dedicated server, relay and proxy in the same tree, with passwords kept off the command line.

Distribution in single-user validation

One command. No clone.

Version 2.4.0 is the one the maintainer uses, on an Apple M3 Mac, and it does not offer general public support yet. Its technical classification is owner-only; the external-public audience has not been authorized yet.

Before you start: nothing to install beyond the system. macOS and Linux use curl; Windows uses the PowerShell it ships with. The bootstrap downloads the x86QW native CLI over HTTPS and checks its size and SHA-256 before running it; on macOS and Linux, a truncated download of the script runs nothing.

What works today, and for whom.

Capabilities and limits, described without turning internal evidence into a public promise.

Recorded use: version 2.4.0 in use by the maintainer on an Apple M3. There is no record of native validation on Linux and Windows; those platforms and the services stay in preview.

Available content: 28 packages, 21 components, five games, KTX with 24 modes and Frogbots, plus MVDSV, QTV and QWFWD. Stable and nightly can live side by side.

Verifiable integrity: the installer authenticates the catalog with TUF and accepts only files that match the published size and SHA-256. GitHub Releases and GitLab Generic Packages serve as mirrors.

The macOS limit: the stable client keeps the upstream bundle, which has no Developer ID and no proven notarization. That is why its support stays conditional.

Conservative operation: passwords stay off the command line; x86qw host uses loopback by default, the server the installer builds says that it accepts the network and offers “Only this machine”, and the running stack can be inspected and stopped in a coordinated way.
